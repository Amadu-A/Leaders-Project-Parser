# Проверка реализации

Проверки: 13 и 16.11.2026. Локальная среда: Windows, Python 3.14.7; целевой образ — Python 3.12 на Debian bookworm с Chromium Headless Shell Playwright v1.65.1.

Проверено автоматически:

- `ruff check .` и `ruff format --check .`.
- 76 pytest-сценариев с настоящим Chromium, локальным API и изолированной PostgreSQL 16.15.
- 71 основной сценарий повторно выполнен в Linux/Python 3.12; пять отдельных Excel-тестов выполнены в Windows.
- Два Node.js-теста правил состояний интерфейса.
- `alembic upgrade head` и `alembic check` на PostgreSQL.
- Concurrent start, unique active slot, эксклюзивный advisory lock worker.
- Восстановление частичного результата новым Collector и после закрытия PostgreSQL-пула.
- Каталоги на 1/100/351 запись, кнопочная пагинация, смена списка и активного номера, последняя страница и restart между страницами.
- RSC-запрос активной Next.js-карточки проходит; явный prefetch и запросы соседних карточек не отправляются.
- Публичная JSON-схема, opaque cursor с URL-encoding, цикл cursor, последняя страница, отсутствие поля отдельно от пустого списка, общий bundle карточки/контактов и его сброс на паузе/рестарте.
- Полный индекс до первого запроса карточки, дедупликация URL, конфликты видимых ИНН и расхождение с реквизитами.
- Руководитель отдельно от учредителей, несколько телефонов/email/сайтов, отсутствие контактов отдельно от непроверенной страницы.
- Общий limiter и bounded retries, total deadline, HTTP 403/404/408/429/500, CAPTCHA, Retry-After в секундах и HTTP-date, durable cooldown после пересоздания limiter.
- Ожидающие браузерные ресурсы не сокращают cooldown; повторный 429 на другом URL также останавливает очередь. Длительная пауза Retry-After не расходует deadline ожидания DOM.
- Pause/resume/cancel, API Basic Auth, CSRF, серверный поиск, просмотр контактов и повторное скачивание.
- Formula injection не создаёт формул. ИНН и телефоны — строки, ведущие нули сохраняются. Контакты не обрезаются молча при превышении ограничений Excel.
- Генерация 37 000 синтетических строк при запрещённом `tempfile.mkstemp`. Контроль формата XLSX выполнен из BytesIO, файл не сохранялся.

Измерение Excel на Windows: около **1,92 с**, peak RSS относительно начального процесса **98,7 МиБ**, размер XLSX **1,11 МиБ**. Синтетическая строка содержит два телефона, два email и сайт; результат не является верхней оценкой RAM для произвольных данных. API ограничивает одновременное создание отчётов одним экспортом.

Реальный источник:

- Robots, условия и публичные HTTP-страницы проверены.
- 13.11.2026 в настоящем Chromium увидены 37 710 компаний и 378 страниц по 100.
- 16.11.2026 production-loader получил актуальное число 37 715 и перешёл кнопкой на `?page=2&size=100`: обе страницы содержали по 100 непересекающихся URL.
- Публичные карточки в HTTP-ответе не содержат данные до исполнения JavaScript.
- Полный сбор не запускался.
- Последующие малые smoke-попытки из Windows столкнулись с непостоянными TLS `ConnectTimeout`; отдельные запросы получали HTTP 200. Это сетевое ограничение не считается успешным smoke трёх организаций.
- После проверки публичной JSON-схемы основной режим переведён на HTTP/API. Проба 16.11.2026 успешно обработала две непересекающиеся страницы по 100 записей и три компании: руководители проверены, телефонов 5/6/5, email 5/4/2, по одному сайту. Значения контактов в логи не выводились.
- В этой пробе `total=37 717`; отдельно проверены `offset=100`, равнозначный `nextCursor`, и последняя страница из 17 записей с `nextCursor=null`.
- Браузерный режим карточек не засчитан как успешный live smoke: ожидаемые секции в нём не появились. Основной режим получает те же публичные данные без Chromium; кнопочная пагинация проверена отдельно.

Docker проверен на Linux / Python 3.12:

- Образ собран, все три контейнера healthy. API слушает только `127.0.0.1:8089`; PostgreSQL не опубликована.
- `/health`, `/ready`, авторизация, HTML, CSS, JS и пустой список заданий проверены HTTP-запросами. Запуск не создал задание.
- Chromium запускается непривилегированным пользователем при read-only root и tmpfs `/tmp`; настоящий браузер загрузил интерфейс без JavaScript-ошибок.
- API и worker пересозданы с синтетическим paused-заданием: статус, завершённая карточка и pending-контакты сохранились. Частичный XLSX скачан и проверен из BytesIO; синтетическое задание после проверки удалено.
- `alembic check` внутри целевого контейнера: новых операций нет.

Из-за медленного CDN официальный Chromium загружен через Windows и временный локальный кэш стандартного установщика Playwright. ZIP проверен по размеру и CRC: 131 998 580 байт, SHA-256 `18352d22cb0cdf520cbff2ad8c41391f0e02a72886cb53b0fde4bdfc4bd075d6`. Кэш-сервер остановлен после установки; в Dockerfile не задано стороннее зеркало по умолчанию. Первичная сборка также выявила отсутствие `libatomic1` для bundled Node.js; зависимость добавлена.

Сервер aistation из этой среды не администрировался. Актуальная занятость 8089, firewall, запуск на сервере и многодневный полный сбор должны проверяться оператором по README. Локальные тесты не заменяют эту проверку.
